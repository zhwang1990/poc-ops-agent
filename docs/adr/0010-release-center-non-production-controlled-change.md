# ADR 0010：发布中心非生产受控变更边界

- 状态：Accepted
- 日期：2026-07-01
- 负责人：平台与安全负责人
- 相关模块：M02、M03、M05、M07、M08、M09、M10、M11
- 相关任务：发布中心 P2 受控变更试点

## 背景

平台需要提供面向内部应用的发布、启停、重启、回滚和日志分析能力，覆盖 `dev`、`sit`、`uat` 三类非生产环境，并支持 Tomcat 与 WebSphere Liberty 这两类服务器。该能力会对目标系统产生副作用，不能进入 P1 只读诊断 MVP。

用户已确认以下产品约束：

- 菜单名称使用“发布中心”，避免过长导致菜单换行。
- Tomcat 和 Liberty HTTPS 初始只支持 WAR 制品；Liberty 脚本 Profile 可以不绑定平台上传制品，前提是控制面保存的已审核 Profile 参数模板不引用平台制品上下文。
- 单次发布面向一个应用、一个环境、多节点串行执行。
- `sit` 和 `uat` 至少需要二次确认，该要求可通过服务端策略配置。
- Liberty 可以复用现有 HTTPS 服务，也可以通过已经安全评审、由控制面脚本 Profile 页面维护的受控定义完成非生产发布；发布单和服务器配置只引用 Profile ID 和受约束参数，不允许临时填写脚本路径或命令。
- Tomcat 初期提供页面上传 WAR 按钮，目标执行方式通过策略扩展。
- 成功或失败必须由确定性检查判定，大模型只能分析脱敏日志并给出诊断建议。

## 决策

- 发布中心作为 P2 非生产受控变更切片交付，不属于 P1 只读 MVP。
- 发布中心不新增独立部署服务，也不新增模块编号；控制面侧归属于 M05/M09 业务模块组合，Worker 侧归属于 M07/M08 适配器。
- 控制面只负责配置、策略、审批、工作流、幂等、事件和审计，不直接连接目标服务器、不执行脚本、不持有目标系统长期明文凭据。
- Worker 只接受已经授权、带版本、带参数哈希和幂等键的执行请求，不自行做授权决策。
- 发布中心仅允许 `dev`、`sit`、`uat` 环境。生产环境不可配置、不可见、不可调用。
- 执行模式采用显式管理模式：
  - `LIBERTY_HTTPS`：由 Worker 调用已配置的 Liberty HTTPS 发布服务，仍受 HTTP 出口 allowlist 约束；
  - `LIBERTY_SCRIPT_PROFILE`：由 Worker 调用控制面随已授权请求下发的已审核脚本 Profile 定义。控制面脚本 Profile 页面可以维护 `executablePath`、`workingDirectory`、参数模板、参数白名单、超时、成功退出码、审核和启用状态；发布单和服务器配置只能传 `profileId` 与 `name/value` 参数，不能临时传脚本路径、命令行或 shell 片段；参数不得携带密码、密钥或 token，敏感材料只能通过凭据别名或短期凭据边界提供；当 Profile 参数模板不引用 `{{artifactPath}}`、`{{artifactId}}`、`{{artifactStorageKey}}` 或 `{{artifactChecksum}}` 时，发布单可以不绑定制品；
  - `TOMCAT_WAR_UPLOAD`：由操作台上传 WAR，控制面保存受控制品引用，Worker 后续按配置策略部署；
  - 预留 `TOMCAT_MANAGER_API`、`NODE_AGENT_HTTPS` 和 `CONTROLLED_SSH_TEMPLATE` 策略，但未完成 ADR、安全评审和测试前不得启用。
- 服务器适配采用可插拔 Skill 驱动模型。每个发布、启停、回滚和日志分析动作都必须有版本化 Skill 契约、风险等级、输入输出 Schema、权限、超时、重试策略和测试用例。
- 初始编排采用串行节点执行。后续并行、分批或灰度必须重新补充契约、恢复语义和安全评审。
- 成功或失败由确定性状态检查判定，包括工作流终态、节点动作结果、目标进程或服务状态、端口、健康检查 URL、当前版本、制品校验和、超时与回滚状态。
- 大模型日志分析只作为只读诊断 Skill 接入，输入必须脱敏，输出只能是建议、可疑原因和下一步检查项，不能改变工作流状态、不能授予权限、不能替代确定性结果。

## 配置与凭据边界

- 发布中心配置通过操作台页面维护，风格与“模型设置”一致：管理员可配置应用、环境、服务器、制品策略、确认策略、健康检查、超时、回滚和凭据别名。
- 凭据可由页面录入，但服务端必须加密保存，只返回指纹、别名、更新时间和状态，不返回明文。
- 后续如接入 Vault、短期凭据或目标系统委托令牌，应保持凭据别名和指纹契约稳定。
- 所有配置变更必须经过服务端策略授权、审计和版本化记录。

## 安全门禁

发布中心执行前必须满足：

1. 操作人身份可信，动作通过 M02 服务端策略。
2. 目标环境属于 `dev`、`sit`、`uat`，且目标应用和服务器处于启用状态。
3. Skill 版本、目标、参数哈希、策略版本、确认或审批引用已绑定。
4. `sit` 和 `uat` 的二次确认或更严格审批已满足，关键内容变化后自动失效。
5. 制品引用与制品哈希，或 Liberty 脚本 Profile ID 与参数哈希，已经和目标服务器、健康检查、回滚策略一起持久化。
6. 工作流具备幂等键、恢复语义、终止状态、失败事件和人工接管路径。
7. Worker 出口、凭据、协议和目标地址均受 allowlist 或等价配置约束。
8. 审计事件、指标、结构化日志和 trace 已覆盖配置、确认、执行、失败、回滚和人工接管。

## 影响

- 需要新增发布中心领域契约、语义事件契约、Worker 命令契约和 Skill 契约包。
- 需要新增发布中心配置和工作流持久化表。
- 需要扩展 M02 RBAC 动作和审计事件类型。
- 需要新增 M07/M08 的 Liberty 与 Tomcat 策略适配器，且必须默认失败关闭。
- 操作台需要新增“发布中心”菜单与管理页面，但不得绕过服务端策略、确认、审批或审计。

## 明确不做

- 不支持生产环境发布、启停、回滚或日志读取。
- 不触发 CI 构建流水线。
- 不支持任意脚本执行；只允许控制面已审核、参数 Schema 受限、随授权请求下发且 Worker 不经过 shell 执行的 `LIBERTY_SCRIPT_PROFILE`。
- 不把模型分析作为最终成功或失败判定。
- 不新增多租户、外部客户接入、计费或租户隔离。
- 不把每一种服务器类型实现为独立部署服务。

## 发布与回滚

发布中心必须通过独立功能开关启用，默认关闭。回滚时关闭发布中心执行入口，保留只读查询、配置审计和历史工作流读取；撤销 Worker 侧目标系统凭据和出口配置；未完成工作流进入可审计的人工接管状态。
