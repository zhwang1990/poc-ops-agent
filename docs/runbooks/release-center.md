# 发布中心运行手册

## 适用范围

本手册适用于 P2 发布中心非生产受控变更切片。发布中心只覆盖 `dev`、`sit`、`uat` 环境的 WAR 制品发布、Liberty 脚本 Profile 发布、启动、停止、重启、回滚和只读日志分析，不覆盖生产环境。

## 启用顺序

1. 确认 ADR 0010 已通过评审，相关契约、策略、工作流、Worker 适配器、前端页面和测试证据已随版本发布。
2. 在控制面启用发布中心只读配置查询功能，保持执行入口关闭。
3. 配置应用、环境、服务器、制品策略、健康检查、超时、确认策略和回滚策略。
4. 为 Worker 配置目标系统出口 allowlist 和凭据别名，确认凭据明文不会出现在日志、审计、Prompt、配置示例或测试数据中。
5. 在 `dev` 环境启用执行功能开关，完成单节点和多节点串行 smoke。
6. 在 `sit` 环境启用执行功能开关，验证二次确认、失败停止和人工接管。
7. 在 `uat` 环境启用执行功能开关，验证回滚、日志分析和审计追踪。

生产环境不得启用发布中心执行能力。

## 环境开关

发布中心至少需要以下开关或等价部署参数：

- 控制面发布中心总开关，默认关闭。
- 按环境执行开关，`dev`、`sit`、`uat` 分别控制，默认关闭。
- Tomcat WAR 上传开关，默认关闭。
- Liberty 脚本 Profile 发布开关，默认关闭；已审核 Profile 可以封装调用 HTTPS / JAR 发布能力的成熟脚本。
- Liberty 脚本 Profile 配置，默认空配置；未配置已审核 Profile、Profile 未启用或服务器脚本参数不满足已审核定义时控制面和 Worker 必须失败关闭。
- 日志分析只读 Skill 开关，默认关闭。

任何开关开启前必须确认对应策略、审计、指标和告警已经生效。

## 策略角色

发布中心默认策略必须给发布操作员角色 `ROLE_ops-release` 开放非生产发布所需动作：`release.catalog.read`、`release.catalog.write`、`release.connection.test`、`release.plan.create`、`release.plan.confirm`、`release.plan.execute` 和 `release.rollback.execute`。其中 `release.catalog.write` 覆盖应用目录、服务器目录和通用 Script Profile 的页面维护能力；如果外部 OIDC 部署使用独立配置文件，必须同步这些规则，否则页面会出现 `no policy rule for request` 或 Script Profile 读取失败。

`release.credential.rotate` 仍只允许 `ROLE_ops-admin`，发布操作员只能在服务器配置中引用已受控登记的凭据别名，不能轮换或查看凭据明文。

## Liberty 脚本 Profile

Liberty 脚本发布只允许执行已经安全评审并在控制面脚本 Profile 页面登记、审核、启用的脚本 Profile。Profile 是跨 `dev`、`sit`、`uat` 复用的通用脚本定义，页面可以配置 `executablePath`、`workingDirectory`、可选参数模板、超时、成功退出码、审核状态和启用状态；新增或修改服务器时只能引用 `scriptProfile.profileId` 并填写当前节点的 `name/value` 脚本参数，发布单不能填写脚本路径、命令行、shell 片段或明文密钥。

Liberty 发布不要求操作台上传制品，但必须在脚本参数中提供 `artifactPath`。`artifactPath` 是以 `\\` 开头的共享目录路径，例如 `\\jenkins\share\orders\latest\orders.war`，通常作为脚本第三个参数传给经评审脚本，由脚本调用成熟 JAR / HTTPS 发布能力读取制品。控制面创建发布单时不绑定平台上传制品，但会要求所有启用的 Liberty 脚本节点都配置 `artifactPath`，并把该值纳入参数哈希。Worker 仍必须只执行控制面随已授权请求下发的已审核 Profile 定义，不得接受发布单临时传入的脚本路径或命令行。

脚本 Profile 定义和 Worker 二次校验必须至少约束以下内容：

- `executable-path`：审核过的脚本或包装程序绝对路径。
- `arguments`：可选参数模板；填写后只能引用 `{{artifactPath}}`、`{{applicationId}}`、`{{nodeId}}`、`{{managementEndpoint}}`、`{{applicationPath}}`、`{{credentialAlias}}` 和 `{{param.<name>}}` 等受控占位符；其中 `{{param.<name>}}` 的值必须来自服务器配置中的脚本参数。模板为空时，Worker 按服务器脚本参数的行顺序把参数值传给脚本。
- 服务器脚本参数：不同节点可以传不同 `name/value`，例如 `serverName`、`applicationName`、`artifactPath`；参数名和值必须通过 Worker 二次校验，模板引用缺失或空模板下缺少节点参数时必须拒绝执行。
- `timeout` 和 `success-exit-codes`：超时与成功退出码；超时或非成功退出码必须返回失败状态。
- `artifact-storage-path` 和 `working-directory`：受限工作区；脚本不得从操作台输入中获得任意文件路径。

脚本参数不得携带 `password`、`secret`、`token` 等敏感材料。需要凭据时只允许使用凭据别名或短期凭据边界，且不得把明文写入日志、审计、Prompt、制品或测试数据。

脚本标准输出和标准错误由 Worker 合并写入 Profile 的 `workingDirectory` 下，文件名格式为 `release-script-<executionRequestId>.log`。Worker 同时把输出转换为 `RELEASE_NODE_LOG` 语义事件，经控制面 SSE 接口转发到操作台发布单行内的“脚本输出”区域。该实时输出只包含脱敏后、最长 1000 字符的单条 stdout/stderr 文本，用于观察执行进度；前端不得直接读取 Worker 文件系统，最终成功或失败仍以确定性节点结果和工作流事件为准。

## 服务器配置维护

操作台允许在 `dev`、`sit`、`uat` 范围内新增、修改和删除发布服务器配置。修改服务器时节点 ID 保持只读；如果需要更换节点 ID，必须新增一个节点并删除旧节点。删除服务器只移除发布中心目录配置，不会删除目标系统上的服务、制品、脚本或历史工作流记录；历史发布单仍以当时绑定的节点、参数哈希和审计事件为准。

## 凭据轮换

1. 在操作台录入或更新目标系统凭据，服务端只返回凭据指纹和更新时间。
2. 使用非生产目标执行受控连通性探测，不回显目标系统响应体中的敏感字段。
3. 确认新凭据可用后，将服务器配置切换到新凭据别名。
4. 保留旧凭据到所有在途工作流结束或进入人工接管状态。
5. 撤销旧凭据，并记录审计事件、操作者、影响范围和回滚方式。

## 失败停止

串行节点发布时，任一节点出现以下情况必须停止后续节点：

- 制品哈希或版本校验失败。
- 上传、部署、启动、停止或回滚动作失败。
- 健康检查 URL、端口、进程或当前版本检查超时。
- Worker 返回出口、凭据、协议或目标地址拒绝。
- 工作流检测到确认、审批、参数哈希或策略版本失效。

停止后，工作流必须发布失败事件并进入可审计终态或人工接管状态。操作台不得根据展示文本推断状态，只能消费强类型语义事件。

## 回滚

回滚执行前必须确认：

- 上一个稳定版本、制品哈希和部署路径可用。
- 回滚目标服务器、环境和应用与原发布工作流一致。
- 回滚动作经过服务端策略授权，必要时重新确认或审批。
- 回滚 Skill 版本、参数哈希、策略版本和幂等键已绑定。

回滚成功或失败同样由确定性状态检查判定。大模型日志分析只能解释可能原因，不能改变回滚状态。

## 人工接管

以下情况必须进入人工接管：

- 回滚策略缺失或上一个稳定版本不可用。
- Worker 适配器无法判断目标系统真实状态。
- 目标系统返回不一致状态，例如进程存在但健康检查持续失败。
- 凭据或网络出口异常导致平台无法安全继续。
- 工作流恢复后无法确认上一次副作用动作是否完成。

人工接管记录必须包含 workflowId、目标应用、环境、服务器、操作人、最后成功步骤、失败步骤、已执行补偿、建议处理动作和审计 trace。

## 日志分析

日志分析 Skill 只允许读取脱敏后的非生产日志片段或平台受控制品。输出内容只能包含摘要、可疑原因、证据片段位置和建议检查项，不得包含模型内部推理，不得输出敏感字段，不得作为成功或失败判定依据。

## 回退发布中心

1. 关闭 `uat` 和 `sit` 执行开关，确认无新工作流进入执行。
2. 关闭 `dev` 执行开关。
3. 保留历史工作流、审计和只读配置查询。
4. 撤销 Worker 目标系统出口和凭据。
5. 将所有非终态工作流标记为人工接管，并记录停用原因。
6. 验证操作台只展示历史和配置，不再暴露执行按钮。

## 失败注入记录格式

每次在 `dev`、`sit` 或 `uat` 执行失败注入时，记录必须包含：

- workflowId、目标环境、目标应用、服务器节点和操作者。
- 注入的失败类型，例如制品哈希不匹配、上传失败、健康检查超时、凭据拒绝或策略版本失效。
- 预期语义事件、实际语义事件、终态状态和事件序号范围。
- 后续节点是否被阻断，以及阻断证据。
- 回滚动作、补偿动作或人工接管路径。
- 审计 trace、策略版本、Skill 版本、参数哈希和幂等键。
- 验证人、验证时间、结论和遗留问题。

## 回滚演练记录格式

每次回滚演练必须记录：

- 原发布 workflowId、回滚 workflowId、目标应用、环境和服务器节点。
- 上一个稳定制品版本、制品哈希、部署路径和可用性确认方式。
- 回滚策略、确认或审批引用、Skill 版本、参数哈希、策略版本和幂等键。
- 回滚动作序列、确定性状态检查结果、健康检查结果和最终状态。
- 大模型日志分析输入引用、输出摘要和它没有参与状态判定的说明。
- 审计 trace、操作者、复核人、演练时间和是否需要人工接管。
