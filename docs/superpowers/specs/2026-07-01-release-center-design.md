# 发布中心非生产应用发布设计

- 日期：2026-07-01
- 相关模块：M02、M03、M05、M07、M08、M09、M10、M11
- 目标阶段：P2 受控变更试点，P3 生产加固前置能力
- 菜单名称：发布中心
- 任务切片：非生产环境应用发布、启停、回滚与日志分析
- 状态：已确认设计，待实现计划
- 设计结论：首版采用“统一发布工作流 + 可插拔服务器适配器”。发布中心只覆盖 `dev`、`sit`、`uat`，不包含生产环境；制品不由平台触发构建；Liberty 通过现有 HTTPS 服务读取远程制品目录并执行上传/部署；Tomcat 仅支持操作台上传 `WAR` 到平台受控制品记录后再发布。工作流统一负责策略、二次确认、串行节点执行、幂等、失败停止、回滚、人工接管、语义事件和审计。适配器只执行标准动作，不决定权限。大模型只能分析脱敏日志并给出诊断建议，不能作为最终成功或失败裁判。

## 背景

当前项目优先级仍是 P1 只读诊断 MVP。P1 的 Skill 源包工具、Worker 执行请求和 Agent Tool 执行链路都明确固定在只读能力上。新的发布、启停和回滚能力属于有副作用的受控变更，不能复用 P1 的 `READ_ONLY` 命令信封直接承载，也不能让 Agent、前端或 Skill 绕过服务端策略和工作流事实源直接调用目标系统。

用户希望新增一个短菜单入口，用于打包后应用的发布、启停和回滚，覆盖 `dev`、`sit`、`uat` 三类非生产环境，服务器类型首版包含 Tomcat 和 Liberty，并要求能力可插拔、Skill 驱动、高扩展性。经过需求收敛，首版不触发 CI 构建，只消费已存在或上传登记的制品；发布粒度为单应用、单环境、多节点串行；`sit` 和 `uat` 使用服务端可配置的二次确认策略；凭据可在页面录入并加密保存，只返回指纹；大模型可以参与日志分析，但最终状态必须由确定性检查和 M05 状态机决定。

## 目标

- 在操作台新增短菜单 `发布中心`，承载非生产应用发布、启停、回滚和配置管理。
- 建立应用、环境、服务器、凭据、制品和发布单目录，操作员只能选择已登记目标，不得临时输入任意主机、路径、命令或明文凭据。
- 支持 `dev`、`sit`、`uat`，首版不出现生产环境。
- 支持单应用、单环境、多节点串行发布。
- `sit` 和 `uat` 的二次确认策略由服务端配置决定，前端不能降低。
- Liberty 首版通过现有 HTTPS 服务读取制品目录并完成上传/部署。
- Tomcat 首版只支持 `WAR` 上传，上传后进入平台受控制品记录，再由发布工作流部署。
- 通过可插拔适配器隔离 Tomcat、Liberty 和后续服务器类型差异。
- 每个发布、启停、回滚动作都具备持久化工作流、幂等、审计、语义事件、失败停止和人工接管路径。
- 接入大模型日志分析作为只读诊断辅助，输出疑似原因、证据行、置信度和建议动作。

## 非目标

- 不支持生产环境发布、启停或回滚。
- 不触发 CI 构建，不实现打包流水线。
- 不做多应用编排或并行发布。
- 不执行任意脚本、任意 shell、任意 URL 或任意路径。
- 不让模型、Prompt、前端输入或 Skill 说明降低策略、确认、审计或隔离要求。
- 不让大模型作为最终成功或失败判定来源。
- 不在首版确定长期对象存储产品选型；制品暂存和对象存储实现需要单独 ADR。
- 不新增租户、多租户、计费、外部客户接入或商业开放平台能力。

## 设计范围追溯

本设计对应 V8.1 和当前规划中的以下能力：

- M02：发布、启停、回滚、配置、凭据和二次确认的服务端授权与审计。
- M03：发布类 Skill 或动作契约、风险等级、版本、签名和发布治理。
- M05：受控变更工作流、二次确认、幂等、状态恢复、回滚和人工接管。
- M07：受限 Worker、受控网络出口、凭据边界和目标系统执行隔离。
- M08：Tomcat、Liberty 和后续服务器类型的目标系统适配器。
- M09：发布中心页面、强类型语义事件、进度展示、失败展示和人工操作入口。
- M10：日志、指标、追踪、审计保留、告警和运行手册。
- M11：契约测试、安全测试、回滚演练和发布门禁。

该能力属于公司内部自研自用、单组织部署的受控变更能力，不改变产品边界。

## 方案选择

已确认采用方案 1：统一发布工作流 + 可插拔服务器适配器。

```text
发布中心
  -> M01 身份认证
  -> M02 策略授权
  -> M03 发布类 Skill / 动作契约
  -> M05 发布工作流与二次确认
  -> M07 受限 Worker
  -> M08 Tomcat / Liberty 适配器
  -> M09 语义事件和页面展示
  -> M02 / M10 审计与可观测
```

不采用 Liberty 和 Tomcat 两套独立发布流程，避免回滚、审计、状态机和日志分析重复分叉。也不采用“每个操作一个 Skill 直接串联执行”的方式，避免 Skill 编排替代 M05 工作流状态机。

## 架构边界

M09 页面可以配置应用、环境、服务器、凭据和 Tomcat WAR 上传，但所有配置变更都必须经过 M02 授权和审计。

M03 负责发布类 Skill 或动作契约。P2 发布类能力不能继续使用 P1 固定的 `READ_ONLY` 风险等级；应按动作和环境使用 `LOW`、`MEDIUM` 或后续策略风险等级。当前 P1 的 Skill 源包工具仍固定只读，P2 实现前必须扩展契约和工具，并保持只读链路兼容。

M05 是发布事实源。发布单、二次确认、节点串行状态、参数哈希、适配器版本、失败停止、回滚状态和人工接管状态都必须持久化。

M07 Worker 只接受已授权、带版本、短期有效的执行请求。Worker 不得自行授权，不得接受自由命令，不得持有控制面可直接读取的长期目标凭据。

M08 适配器只实现标准动作，不决定是否可执行。新增 `serverType` 或 `managementMode` 时，只新增适配器和策略配置，不改发布主工作流。

大模型日志分析作为只读辅助能力接入。模型输出、日志片段和适配器输出都视为不可信数据，只能进入诊断报告和人工参考。

## 配置目录

首版由发布中心维护以下目录。

| 目录 | 作用 |
|---|---|
| 应用目录 | 应用 ID、应用名、制品类型、默认健康检查路径、所属系统、启用状态 |
| 环境策略 | `dev`、`sit`、`uat` 是否允许发布、启停、回滚、是否需要二次确认、超时时间、串行失败策略 |
| 服务器目录 | 节点 ID、环境、`serverType`、管理模式、地址、端口、应用路径、启用状态 |
| 凭据目录 | 凭据别名、适用服务器类型、加密密文、指纹、更新时间 |
| Liberty 制品源 | Liberty HTTPS 服务地址、远程目录策略、应用到目录的映射 |
| Tomcat 制品库 | 上传 WAR 后生成的制品记录、版本、checksum、大小、上传人、适用应用和环境 |
| 发布单 | 应用、环境、制品引用、节点列表、动作、二次确认记录、参数哈希、状态、审计 trace |
| 节点步骤 | 每个节点的 `precheck`、`deploy`、`start`、`healthcheck`、`log-analysis`、`rollback` 状态和证据 |

凭据录入体验可以接近模型设置页：管理员录入或轮换后，服务端加密保存，页面只显示指纹。任何 API、日志、事件、Prompt、测试样例或制品都不得回显明文凭据。

## 制品来源

首版支持两种制品来源策略。

| 服务器类型 | 制品来源模式 | 行为 |
|---|---|---|
| `LIBERTY` | `REMOTE_DIRECTORY` | 调用现有 Liberty HTTPS 服务读取远程制品目录，并由该服务完成上传或部署 |
| `TOMCAT` | `OPERATOR_UPLOAD` | 操作台上传 `WAR`，平台校验并登记为受控制品记录，发布流程再使用该记录部署 |

Tomcat 上传按钮不得直接把 WAR 推到目标 Tomcat。上传必须先进入平台制品接收流程，生成 `artifactId`、版本、大小、checksum、上传人、适用应用和环境。发布单只能引用已登记、已校验、未禁用的制品。

制品实际存储首版应通过“受控制品暂存区”抽象表达。开发态可以使用受限本地目录；生产化前必须通过 ADR 决策对象存储或制品库实现、保留策略、清理策略、容量告警和回滚恢复方式。

## 服务器适配器

首版适配器：

- `LIBERTY_HTTPS`：调用现有 Liberty HTTPS 管理服务，支持远程目录读取、上传/部署、启停、健康检查和日志采集。
- `TOMCAT_WAR_UPLOAD`：使用平台已登记 WAR 制品，按 Tomcat 策略部署、启停、健康检查和回滚。

预留适配器：

- `TOMCAT_MANAGER_API`
- `NODE_AGENT_HTTPS`
- `CONTROLLED_SSH_TEMPLATE`

服务器目录通过策略选择管理方式：

```text
serverType: TOMCAT | LIBERTY
managementMode: LIBERTY_HTTPS | TOMCAT_WAR_UPLOAD | TOMCAT_MANAGER_API | NODE_AGENT_HTTPS | CONTROLLED_SSH_TEMPLATE | DISABLED
actionCapabilities: DEPLOY | START | STOP | RESTART | ROLLBACK | LOG_ANALYSIS
```

统一适配器接口：

- `precheck(context)`
- `deploy(context)`
- `start(context)`
- `stop(context)`
- `restart(context)`
- `rollback(context)`
- `healthcheck(context)`
- `collectLogs(context)`

适配器不得接收任意 shell 内容。即使未来新增受控 SSH 模板，也只能执行平台版本化模板和白名单参数，不能让用户在页面输入任意命令。

## 发布工作流

首版发布单按串行节点执行。

```text
DRAFT
  -> WAIT_CONFIRM
  -> READY
  -> RUNNING
  -> SUCCEEDED | SUCCEEDED_WITH_WARNINGS | PARTIAL_FAILED | FAILED | MANUAL_INTERVENTION
  -> ROLLING_BACK
  -> ROLLED_BACK | ROLLBACK_FAILED | MANUAL_INTERVENTION
```

节点执行顺序：

1. `precheck`：校验目录、策略、连通性、凭据、节点锁、当前版本快照。
2. `deploy`：Liberty 调 HTTPS 服务；Tomcat 使用平台制品库中的 WAR。
3. `start` 或 `restart`：按发布动作和环境策略执行。
4. `healthcheck`：检查进程或服务状态、端口、管理接口、健康 URL、当前部署版本。
5. `log-analysis`：可选调用大模型分析脱敏日志，只输出诊断建议。

失败策略：

- 默认某个节点失败后停止后续节点。
- 不自动回滚，先让操作员确认是否回滚已成功节点。
- 回滚对已成功节点按反向顺序串行执行。
- 回滚必须使用上一版本快照和 checksum，不能临时选择任意包。
- 状态不确定、回滚失败或节点无法确认最终状态时进入人工接管。

幂等策略：

- 发布单使用应用、环境、制品、节点列表、动作、策略版本、适配器版本和参数哈希生成幂等语义。
- 重复请求命中已完成状态时返回已有结果，不重新执行。
- 节点已处于目标状态时返回 `NOOP_ALREADY_IN_TARGET_STATE`，仍记录事件和审计。

## 成功和失败判定

最终状态由确定性信号和 M05 状态机决定，不由命令退出码单独决定，也不由大模型决定。

| 动作 | 成功标准 | 失败标准 |
|---|---|---|
| 制品校验 | 制品来源受信，应用、版本、环境匹配，checksum 通过 | 制品不存在、checksum 不一致、环境不匹配、来源未登记 |
| 发布前检查 | 目标在目录内，环境允许，节点未锁定，连通性、权限、快照通过 | 任一目录、策略、锁、连通性或快照检查失败 |
| 部署 | 目标制品 checksum 一致，上一版本已备份，适配器完成部署切换 | 上传失败、校验失败、备份失败、部署目录异常、适配器不可恢复错误 |
| 启动 | 服务状态为 running，端口或管理接口可用，健康检查通过 | 进程未启动、端口不可用、健康检查失败、超时 |
| 停止 | 服务状态为 stopped，端口释放，重复停止幂等成功 | 停止超时、进程仍在、端口仍占用、需要人工接管 |
| 回滚 | 成功切回上一制品版本，并通过启动和健康检查 | 上一版本缺失、切回失败、健康检查失败 |

如果确定性检查成功，但日志分析发现严重异常模式，可以按环境策略标记 `SUCCEEDED_WITH_WARNINGS` 或进入人工确认。日志分析报告不得覆盖确定性失败，也不得授予继续执行权限。

## Skill 驱动模型

发布中心采用 Skill 和动作契约驱动，但不让 Skill 直接绕过工作流执行副作用操作。

候选发布类 Skill：

- `release-plan-create`
- `release-execute`
- `release-start`
- `release-stop`
- `release-rollback`
- `release-log-analysis-read`

发布类 Skill 必须声明 Owner、版本、分类、风险、执行器、Schema、权限、超时、重试策略、输出契约和测试用例。Skill 正文不得包含 endpoint、凭据、allowlist、脚本、命令或环境专用路径。

Agent 可以帮助创建发布计划、解释失败或分析日志。真正执行必须由 M05 发布工作流触发，并经过 M02 策略、二次确认、参数哈希绑定、M07 Worker 和 M10 审计观测。

## 发布中心页面

菜单名为 `发布中心`，避免侧边栏换行。页面标题同样使用 `发布中心`。设计文档和领域描述可使用完整名称“应用发布与运行控制”。

首版视图：

| 视图 | 用途 |
|---|---|
| 发布单 | 查看发布历史、状态、当前节点、失败原因、回滚入口 |
| 新建发布 | 选择应用、环境、制品、节点，展示策略校验和二次确认 |
| 制品 | Tomcat WAR 上传、checksum、版本、适用环境；Liberty 显示远程目录来源和最近同步状态 |
| 应用 | 应用目录维护、健康检查路径、制品类型、启用状态 |
| 服务器 | Tomcat/Liberty 节点维护、管理模式、地址端口、应用路径、连通性测试 |
| 策略 | `dev/sit/uat` 发布、启停、回滚、二次确认、失败策略和日志分析开关 |
| 凭据 | 录入或轮换凭据，只显示别名和指纹，不回显明文 |

交互规则：

- 发布中显示串行节点进度、当前动作、耗时、健康检查结果和日志分析摘要。
- 失败时分开展示确定性失败原因和模型日志分析建议。
- `sit` 和 `uat` 执行前展示二次确认，确认内容包含应用、环境、制品 checksum、节点列表和影响范围。
- 敏感字段保存后清空，只显示指纹。
- 页面不得提供临时主机、临时路径、自由命令或明文密码输入。

## 安全边界

- 首版只允许 `dev`、`sit`、`uat`。
- 所有配置变更、发布、启停和回滚都经过 M02 授权和审计。
- `sit` 和 `uat` 二次确认由服务端策略要求，前端不能降低。
- 凭据加密保存，只返回指纹，不写入日志、Prompt、事件或制品。
- Worker 只能执行标准动作，不接受自由命令、自由 URL 或自由路径。
- 发布单、确认、制品 checksum、节点列表、策略版本和适配器版本必须绑定参数哈希。
- 大模型只分析脱敏日志，不能决定授权或最终状态。
- 高风险或不可信执行需要进入强隔离环境。Job Object 和 WDAC 只能作为纵深防御，不是完整隔离边界。

实现前必须新增或更新 ADR，明确 P2 非生产发布能力的副作用边界、凭据加密方案、制品暂存方案、Worker 隔离要求和回滚方式。

## 审计和语义事件

审计范围：

- 应用、环境、服务器、策略和凭据配置变更。
- 凭据创建、轮换、禁用和测试连接。
- Tomcat WAR 上传和制品禁用。
- 发布单创建、二次确认、执行、失败、回滚和人工接管。
- 每个节点动作的开始、完成、失败、跳过和幂等命中。

建议新增发布类语义事件：

- `RELEASE_CREATED`
- `RELEASE_CONFIRMED`
- `RELEASE_NODE_STARTED`
- `RELEASE_NODE_COMPLETED`
- `RELEASE_NODE_FAILED`
- `RELEASE_SUCCEEDED`
- `RELEASE_SUCCEEDED_WITH_WARNINGS`
- `RELEASE_PARTIAL_FAILED`
- `RELEASE_ROLLBACK_STARTED`
- `RELEASE_ROLLBACK_COMPLETED`
- `RELEASE_ROLLBACK_FAILED`
- `RELEASE_MANUAL_INTERVENTION_REQUIRED`

事件 payload 只放强类型摘要、标识符、状态、checksum、策略版本、适配器版本和脱敏错误，不放明文凭据或完整敏感日志。

## 测试策略

必须覆盖以下测试：

- 契约测试：发布单、制品、服务器、凭据、发布事件 Schema。
- 策略测试：`dev`、`sit`、`uat` 权限、二次确认、禁用节点、未授权回滚。
- 工作流测试：串行执行、失败停止、幂等、反向回滚、人工接管。
- 适配器测试：Liberty HTTPS 成功/失败、Tomcat WAR 上传校验、健康检查失败。
- 安全测试：任意主机、任意路径、任意命令被拒绝；凭据不回显；日志脱敏。
- 前端测试：发布中心配置、上传、二次确认、发布进度、失败展示、回滚入口。
- 模型评测：日志分析只输出诊断建议，不能产生授权、最终状态或绕过工作流的指令。

发布前必须完成至少一次失败注入和回滚演练，并保留证据。

## 分阶段落地

1. 编写 ADR，锁定 P2 非生产受控发布边界、制品暂存、凭据加密和 Worker 隔离要求。
2. 新增发布中心契约和数据模型，不接真实服务器。
3. 实现发布中心配置页、Tomcat WAR 上传入库和凭据指纹展示。
4. 实现发布工作流状态机、二次确认、节点锁、语义事件和审计。
5. 接入 Liberty HTTPS 适配器。
6. 接入 Tomcat WAR 适配器骨架和受控制品部署路径。
7. 接入日志分析只读 Skill。
8. 完成端到端联调、失败注入、回滚演练和安全评审。

## 发布与回滚

首版发布必须通过功能开关按环境启用，默认关闭。启用顺序应先 `dev`，再 `sit`，最后 `uat`。任何环境启用前必须确认对应服务器目录、凭据、策略、适配器和审计链路完整。

回滚方式：

- 关闭发布中心执行功能开关，保留目录只读查看。
- 禁用对应环境策略或节点。
- 撤销 Worker 中的目标系统凭据。
- 对已创建但未执行的发布单标记取消。
- 对执行中或状态不确定的发布单进入人工接管，不得直接删除事实源。

## 验收标准

- `发布中心` 菜单不换行，并能进入发布单、制品、应用、服务器、策略和凭据视图。
- 操作员只能选择已登记、已启用的应用、环境、制品和服务器。
- Tomcat 只允许上传 `WAR`，并生成 checksum 和受控制品记录。
- Liberty 通过已配置 HTTPS 服务读取远程制品目录。
- `sit` 和 `uat` 执行前必须经过服务端二次确认。
- 多节点发布按串行执行，节点失败后停止后续节点。
- 发布成功、失败、部分失败、回滚和人工接管都有持久化状态、语义事件和审计记录。
- 大模型日志分析只作为辅助报告，不改变最终状态。
- 凭据不回显，日志、事件、Prompt 和测试数据中不包含明文凭据。
- 任意主机、任意路径、任意命令和生产环境请求被拒绝。
