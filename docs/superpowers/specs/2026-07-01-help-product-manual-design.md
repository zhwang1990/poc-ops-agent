# 帮助产品手册设计

## 背景

操作台已经进入 P2 受控变更试点阶段，页面能力从只读诊断扩展到 SQL 工作区开发环境受控 CRUD、发布中心非生产受控变更、模型设置、Skill 注册中心、工作流事件和审计记录。用户需要一个登录后的全局帮助入口，能够用产品语言解释每个页面能做什么、不能做什么，以及典型场景下如何查看结果和边界。

本设计定义首版“帮助”线上产品手册。它服务于操作员、研发人员、运维管理员和审计员，不替代 ADR、运行手册或工程事实源。

## 目标

- 在左侧主导航新增“帮助”入口，进入登录后的全局产品手册页面。
- 帮助页风格与 Agent 工作区保持一致，使用同一套操作台视觉语言。
- 首版提供目录、页面内搜索、核心页面说明、典型场景卡、FAQ 和安全边界。
- 帮助手册内容面向操作员，使用前端内置结构化内容，不接后端、不接 RAG、不调用模型。
- 用户可以搜索“Agent”“权限拒绝”“SQL 校验”“发布失败”等关键词并找到对应场景。

## 非目标

- 不实现 RAG 问答、后端文档索引或模型生成帮助答案。
- 不直接展示仓库 `docs/`、ADR 或运行手册原文。
- 不根据用户角色动态改写手册内容。
- 不新增授权决策、审计事实源或工作流能力。
- 不把帮助页做成登录前公开页面。

## 入口设计

“帮助”作为全局产品能力出现在左侧主导航靠下位置，建议放在“审计记录”之后。路径为 `/help`，和其他工作台页面一样通过 `ProtectedRoute` 保护。

初始导航顺序：

```text
总览
Agent 工作区
RAG 问答
SQL 工作区
模型设置
发布中心
Skill 注册中心
会议录制纪要
AS400对象管理
工作流事件
审计记录
帮助
```

导航图标使用 lucide 的 `CircleHelp` 或同类图标，尺寸、线宽、hover、active 和 tone 机制复用 `AppShell` 现有模式。

## 页面布局

帮助页采用“手册工作台”布局。

- 顶部复用 `WorkspaceStatusBar`，标题为“帮助”。
- 主体使用 `WorkspacePageFrame` 的浅色工作区背景和 `--agent-*` 设计 token。
- 页面主体分三栏：
  - 左侧章节目录：显示章节标题、模块标签和当前选中状态。
  - 中间正文阅读区：显示章节摘要、典型场景、操作步骤、结果解释、边界说明和 FAQ。
  - 右侧本章速览：显示适用角色、相关页面、相关模块、安全边界和常见关键词。
- 正文顶部放搜索框，placeholder 为“搜索场景、页面、错误或权限问题”。
- 窄屏下目录折叠到正文上方，右侧速览移动到正文下方。

页面不使用聊天气泡、问答输入框或模型回复样式，避免用户误解为 AI 问答能力。

## 内容范围

首版覆盖当前核心页面和 P2 启动范围：

1. 快速开始
2. Agent 工作区
3. RAG 问答
4. SQL 工作区
5. 模型设置
6. 发布中心
7. Skill 注册中心
8. 工作流事件
9. 审计记录
10. 权限与安全边界
11. 常见问题

每章使用固定结构：

```text
本章用途
典型场景
操作步骤
结果怎么看
边界与限制
常见问题
```

内容必须使用产品语言。必要时可以提及 M01、M02、M05、M07、M09 等模块，但只用于解释身份、授权、工作流事实源、Worker 隔离和事件展示，不展开工程实现。

## 场景卡模型

典型场景是首版手册的核心。每个主要章节至少包含一个场景卡。场景卡字段固定，便于搜索、渲染和后续迁移。

```js
{
  id: "agent-diagnose-service-errors",
  title: "用 Agent 排查服务错误",
  page: "Agent 工作区",
  roles: ["运维人员", "研发人员", "运维管理员"],
  whenToUse: "某个服务最近报错、响应慢或健康状态异常。",
  prerequisites: ["已登录", "具备只读诊断权限"],
  steps: [
    "进入 Agent 工作区。",
    "在任务目标中描述服务、环境和排查方向。",
    "提交任务后查看 Agent 回复。",
    "查看对话执行状态、已执行 Skill 和执行链。"
  ],
  howToReadResult: [
    "SUCCEEDED 表示只读诊断完成。",
    "REJECTED 表示策略拒绝，不是系统故障。",
    "FAILED_TERMINAL 表示执行失败，需要查看错误码和审计记录。"
  ],
  failureHandling: [
    "策略拒绝时检查角色、目标环境和 Skill 风险等级。",
    "执行失败时查看 workflow 事件和审计记录。"
  ],
  safetyNotes: [
    "Agent 只能调用已授权的只读 Skill。",
    "不能让 Agent 直接重启服务、改配置或执行脚本。"
  ],
  keywords: ["Agent", "只读诊断", "服务错误", "workflow", "Skill", "执行链"]
}
```

首版场景集合：

- Agent 工作区：排查服务错误、查看节点健康、汇总只读诊断结果、查看执行链为什么被拒绝。
- SQL 工作区：查询开发环境数据、校验 SQL 是否只读、执行 DML 影响预检、理解生产连接为什么不可见。
- 发布中心：在 `dev` 发布 WAR、在 `sit` 执行启停或回滚前确认、查看发布失败后的日志分析、进入人工接管。
- 模型设置：新增模型供应方、轮换 API Key、测试连通性失败后判断原因。
- Skill 注册中心：查看 Skill 风险等级和版本、理解未发布 Skill 为什么不会被 Agent 调用。
- 权限与审计：解释按钮不可用、查看某次操作是谁发起的、理解同一按钮在不同角色下状态不同。

## 内容数据模型

首版内容以内置前端结构化数据维护。推荐放在帮助功能目录内，例如 `frontend/operator-console/src/features/help/help-content.js`。

章节模型：

```js
{
  sectionId: "agent-workspace",
  title: "Agent 工作区",
  module: "M04 / M05 / M07 / M09",
  summary: "提交只读诊断任务，查看 Agent 回复、Skill 调用和执行链。",
  roleHints: ["运维人员", "研发人员", "审计员"],
  relatedPages: ["Agent 工作区", "工作流事件", "审计记录"],
  boundary: "只读诊断，不执行生产写操作。",
  keywords: ["Agent", "workflow", "Skill", "只读诊断"],
  scenarios: [],
  faqs: []
}
```

FAQ 模型：

```js
{
  id: "why-button-disabled",
  question: "为什么我看不到某个按钮或按钮不可用？",
  answer: "可能是角色不足、目标环境不允许、功能仍处于禁用态，或该能力需要审批和工作流支持。",
  keywords: ["权限", "按钮不可用", "角色", "禁用"]
}
```

## 搜索行为

搜索只在内置手册内容内执行。

- 搜索范围：章节标题、摘要、模块标签、关键词、场景标题、步骤、结果解释、失败处理、安全边界和 FAQ。
- 搜索结果排序：场景优先，其次章节，最后 FAQ。
- 搜索结果展示：标题、所属章节、命中类型、摘要和标签。
- 点击结果：切换到对应章节，并滚动到对应场景卡或 FAQ。
- 无命中：显示“未找到匹配手册内容”，并展示可点的热门关键词。
- 清空搜索：回到当前章节正文。

搜索不调用模型，不生成答案，不访问后端。

## 视觉规范

帮助页属于产品 UI，设计服务于任务。视觉策略采用克制的操作台风格。

- 复用 Agent 工作区的浅色背景、紧凑面板、细边框、状态徽标和低饱和红/蓝/绿状态色。
- 使用 `WorkspaceStatusBar` 和 `WorkspacePageFrame`，避免建立独立视觉体系。
- 章节目录使用稳定行高和明确 active 状态。
- 场景卡使用编号、标题、标签、步骤列表和安全边界区块，不做相同图标卡片网格。
- 搜索结果使用列表，不使用聊天消息样式。
- 空状态提供热门关键词，不展示模型式回答。
- 动效只用于 hover、active、折叠和滚动定位，时长控制在 150 到 250 ms。

## 可访问性

- 搜索框有明确 `aria-label`。
- 章节目录使用 `nav` 或等价语义区域。
- 搜索结果使用列表结构，结果项可键盘访问。
- 场景卡、FAQ 和右侧速览有清晰 heading 层级。
- 当前章节和当前搜索结果状态不只依赖颜色表达。
- 无命中状态使用 `role="status"` 或等价方式通知。

## 测试计划

首版只需要前端测试，不需要后端契约测试。

- 路由测试：`/help` 是受保护页面，未登录跳转登录，登录后可访问。
- 导航测试：左侧主导航出现“帮助”，点击进入 `/help`，当前项高亮。
- 内容测试：渲染标题、目录、搜索框、核心章节和至少一个典型场景。
- 搜索测试：
  - 搜“Agent”命中 Agent 工作区相关章节或场景。
  - 搜“权限拒绝”命中拒绝或审计相关场景。
  - 搜无匹配词时显示空状态，不生成答案。
- 可访问性测试：搜索框、目录、场景卡和结果列表有语义标签。
- 样式一致性测试：帮助页使用 `WorkspaceStatusBar` 和 Agent 工作区相关 token。
- 响应式验收：至少覆盖现有桌面视口；如已有 Playwright 验收集合，加入 `/help` 可见性断言。

## 验收标准

- 用户能从左侧主导航进入“帮助”。
- 用户能通过目录浏览核心页面手册。
- 用户能搜索场景、权限问题、页面名称和错误词。
- 场景说明包含操作步骤、结果解释、失败处理和安全边界。
- 页面风格与 Agent 工作区一致。
- 帮助页不接 RAG、不调用模型、不绕过登录保护、不暴露工程内部敏感内容。

## 实施边界

实现时应保持变更集中在 `frontend/operator-console`：

- 新增帮助页 feature、内容数据、样式和测试。
- 更新 AppShell 导航和路由表。
- 复用现有布局组件和设计 token。
- 不修改后端、契约、M02 策略、M05 工作流或 M07 Worker。
